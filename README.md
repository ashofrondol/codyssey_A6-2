## 프로젝트 개요

실무의 AI 모델링은 코드를 한 번 돌리고 끝나는 것이 아니라, 성능이 어디서 막히는지 찾고 고치는 일의 반복이다. 이 미션은 두 트랙으로 그 과정을 연습한다. **트랙 A**는 데이터가 적은(Few-shot) 상황에서 이미 다른 큰 데이터로 학습된 모델을 가져와 쓰는 **전이 학습(Transfer Learning)** 으로 이미지를 분류하고, **트랙 B**는 주가 같은 **시계열**(시간 순서대로 쌓인 데이터)을 LSTM/GRU로 예측한다. 두 트랙 모두 Train/Validation/Test 성능 차이로 모델 상태를 진단(**편향 vs 분산**)하고, 틀린 사례를 직접 들여다보는 **오차 분석(Error Analysis)** 을 하며, 딥러닝이 단순한 **베이스라인**(비교 기준이 되는 간단한 방법)보다 정말 나은지를 숫자로 증명한다.

**핵심 과제** (두 트랙 공통 성능 개선 사이클)

1. 베이스라인 설정
2. 딥러닝 모델 적용
3. 편향/분산 진단 및 오차 분석
4. 개선 적용 및 성과 정량화

## 학습 목표

과제를 마치면 아래를 스스로 설명할 수 있어야 한다. (명세 "과제 목표")

- Train/Validation/Test 셋의 Loss 차이로 높은 편향(Underfitting, 덜 배운 상태)과 높은 분산(Overfitting, 학습 데이터만 외운 상태)을 진단하는 방법
- 전이 학습에서 데이터 크기에 따른 최적의 Fine-tuning 범위(Layer Freezing Strategy, 어떤 층을 고정하고 어떤 층을 다시 학습할지)를 정하는 방법
- CNN(이미지)과 RNN(시계열) 모델의 구조적 차이와 적용 도메인
- 오차 분석으로 모델이 실패하는 패턴을 찾고 데이터 증강 전략을 세우는 방법
- 딥러닝 모델과 베이스라인 모델의 성능 차이를 정량적으로 분석하고 해석하는 방법
- 시계열 데이터 처리에서 Data Leakage(학습에 미래 정보가 새어 들어가는 문제)가 생기는 구간과 이를 막는 전처리 원칙

## 개발 환경과 제약 사항

**개발 환경**

- Python 3.10 이상
- PyTorch 또는 TensorFlow를 사용한다.
- GPU 권장(없어도 수행 가능)
- yfinance 사용 시 인터넷 연결 필요. 인터넷이 안 되면 제공 CSV 파일을 써도 된다.

**금지 사항과 지켜야 할 규칙**

- 오차 분석은 반드시 모델이 틀린 실제 데이터를 사람이 직접 확인(Human-in-the-loop)하고 작성한다.
- 시계열 데이터 처리 시 미래 정보가 학습에 들어가는 Data Leakage가 생기지 않도록 반드시 지킨다.
- 베이스라인 모델은 반드시 딥러닝 모델 학습 **전에** 먼저 구현하고 성능을 측정한다.
- 문서 전반에서 용어를 Train/Validation/Test로 통일한다(Dev, Val 등 혼용 금지).
- 금융 시계열에 Jittering/Time-warping 등 증강 기법을 적용하면 데이터 특성이 훼손될 수 있으므로, 시계열 증강은 적용 금지/주의 범주를 반드시 확인한다.

명세의 기능 요구 사항이다. 끝낸 항목은 `[x]`로 바꾼다.

### 1. Few-shot 전이 학습 및 오차 분석 (트랙 A)

큰 이미지 데이터로 이미 학습된 CNN을 가져와, 마지막 분류기만 새로 학습하는 방법(Linear Probing)과 모델 전체를 조금씩 다시 학습하는 방법(Fine-tuning)을 비교한다. 그다음 모델이 틀린 이미지를 직접 보고 왜 틀렸는지 이름표(태그)를 붙인다.

- [ ] 클래스당 50장 미만인 데이터셋을 준비한다.
- [ ] CNN 기반 사전 학습 모델(ResNet, EfficientNet 등)로 전이 학습을 수행한다.
- [ ] 분류기만 학습(Linear Probing)한 성능을 측정한다.
- [ ] 전체 미세 조정(Fine-tuning)한 성능을 측정하고 Linear Probing과 비교한다.
- [ ] 학습 완료 후 오분류된 이미지를 추출한다.
- [ ] 오분류 이미지를 사람이 직접 확인하고 실패 원인을 태깅한다(Human-in-the-loop).
- [ ] 오차 분석표를 작성한다: 실패 원인 태깅 및 통계, **최소 30건 이상**.
- [ ] 태그는 아래 권장 카테고리를 참고한다.

| 태그 카테고리 | 예시 | 개선 방향 |
|---|---|---|
| 데이터 품질 | 어두운 조명, 흐림, 해상도 부족 | 데이터 증강 |
| 배경/잡음 | 복잡한 배경, 객체 가림 | 배경 제거/증강 |
| 클래스 유사성 | 유사 품종, 형태적 유사성 | 특징 학습 강화 |
| 라벨 오류 | 원본 데이터 라벨링 오류 의심 | 데이터 정제 |
| 모델 한계 | 신뢰도는 높으나 잘못 예측, 변별력 부족 | 모델 구조 변경 |

### 2. 시계열 예측 및 베이스라인 비교 (트랙 B)

LSTM/GRU는 앞의 값들을 기억하며 다음 값을 예측하는 RNN 계열 모델이다. "어제 값을 그대로 내일 값으로 쓰기" 같은 아주 단순한 방법과 비교해, 딥러닝이 정말 더 나은지 MAE(평균 절대 오차), RMSE(큰 오차에 더 민감한 오차), MAPE(오차를 퍼센트로 나타낸 값)로 확인한다.

- [ ] yfinance 등으로 주가/경제 데이터를 수집한다(1개 티커, 최소 3년 일봉).
- [ ] Train/Validation/Test를 7/1/2 비율로 시간순 분할한다.
- [ ] 아래 베이스라인 모델 중 **최소 2개**를 딥러닝 모델 학습 전에 먼저 구현하고 성능을 측정한다.
- [ ] 베이스라인 파라미터 가이드를 따른다: SMA 창(window) = 5, 10, 20일 중 선택(각각의 결과 비교 권장), EMA α(alpha) = 0.1, 0.3, 0.5 중 선택, 선형 회귀 입력 피쳐는 시간 인덱스 또는 지연값(lag feature) 기반.
- [ ] LSTM/GRU(RNN 계열)로 예측한다.
- [ ] 모든 모델을 동일한 Test 구간에서 평가한다(공정 비교 규칙).
- [ ] 베이스라인과 딥러닝 모델의 성능을 MAE, RMSE, MAPE 지표로 비교한다.
- [ ] 딥러닝 모델이 베이스라인 대비 몇 % 우수한지 정량화한다.
- [ ] 베이스라인 비교 리포트(비교표)를 작성한다.

| 베이스라인 모델 | 설명 | 수식/방법 |
|---|---|---|
| Naive Forecast | 이전 시점 값을 그대로 예측 | ŷ(t) = y(t-1) |
| 단순 이동평균 (SMA) | 최근 n일의 평균값 | ŷ(t) = (1/n)Σy(t-i) |
| 지수 이동평균 (EMA) | 최근 값에 가중치 부여 | ŷ(t) = αy(t-1) + (1-α)ŷ(t-1) |
| 선형 회귀 | 시간에 대한 선형 추세 | ŷ(t) = at + b |

### 3. 편향/분산 (Bias/Variance) 진단

Train Loss와 Validation Loss를 함께 그려, 둘 다 높으면 덜 배운 것(High Bias), Train만 낮고 Validation이 많이 높으면 외운 것(High Variance)으로 본다.

- [ ] 각 실험에서 Train Loss와 Validation Loss 곡선을 그린다.
- [ ] 두 곡선의 격차(Gap)를 기반으로 High Bias 상태인지 High Variance 상태인지 진단한다.
- [ ] 진단에 따른 솔루션(예: 모델 복잡도 증가 vs 정규화)을 성능 진단 리포트에 명시한다.

| 상태 | Train Loss | Validation Loss | 해결책 |
|---|---|---|---|
| High Bias | 높음 | 높음 (비슷) | 모델 복잡도↑ |
| High Variance | 낮음 | 높음 (큰 격차) | 정규화, 데이터↑ |

### 4. 데이터 누수 (Data Leakage) 방지 체크포인트

시험 문제를 미리 보고 공부하면 점수가 부풀려지듯, 시계열에서 미래 값이 학습에 섞이면 성능이 실제보다 좋게 나온다. 아래 항목을 지키고 리포트에 근거를 적는다.

- [ ] 시간순 분할: 반드시 시간 순서대로 Train → Validation → Test로 분할한다(shuffle 금지).
- [ ] 전처리 Fit 구간 제한: `Scaler.fit()`은 Train 구간에만 적용하고, Validation/Test는 `transform()`만 사용한다.
- [ ] 윈도우 생성 규칙: 입력 윈도우에 미래 시점 값이 포함되지 않도록 확인한다(Look-ahead Bias 방지).
- [ ] 피쳐 생성 시점: 지연값/이동평균 등 피쳐 생성은 분할 전에 수행하고, 문서에 근거를 기술한다.
- [ ] 누수 방지 근거 섹션(Markdown)을 작성한다.

### 5. 실험 결과 시각화 (필수 4종)

- [ ] Train/Validation Loss 곡선: X축 Epoch, Y축 Loss, 두 곡선 오버레이(Gap으로 편향/분산 진단)
- [ ] 예측 vs 실제 그래프(시계열): X축 시간, Y축 값, 실제값(파란선) + 예측값(빨간선) 오버레이
- [ ] 베이스라인 비교 막대그래프: X축 모델명, Y축 MAE/RMSE, 모델별 성능 비교
- [ ] 오분류 이미지 갤러리: 태그별로 그룹화된 오분류 이미지 샘플

### 6. 문서 규칙

- [ ] 문서 전반에서 용어를 Train/Validation/Test로 통일한다(Dev, Val 등 혼용 금지).

## 보너스 과제

### 보너스 1. Hyperparameter Tuning 전략

하이퍼파라미터는 학습률, 층 수처럼 사람이 정해 주는 설정값이다.

- [ ] Grid Search 대신 Random Search 또는 Coarse-to-Fine 전략으로 최적의 하이퍼파라미터를 탐색한다.
- [ ] 탐색 과정과 결과를 시각화한다.
- [ ] 어떤 파라미터가 성능에 가장 큰 영향을 미쳤는지 분석한다.

### 보너스 2. Attention 메커니즘 적용

Attention은 긴 입력 가운데 중요한 부분에 더 집중하게 하는 장치다.

- [ ] LSTM/GRU 모델에 Attention Layer를 추가하거나 Transformer 기반 모델을 적용한다.
- [ ] 긴 시퀀스 데이터에서 Attention의 효과를 확인한다.

## 명세에서 확인할 점

- **용어 통일 규칙과 명세 자체의 표기**: 제약 사항은 "Train/Validation/Test로 통일한다 (Dev, Val 등 혼용 금지)"인데, 명세 본문은 "Train/Dev/Test 셋의 Loss 차이"(과제 목표), "Train/Val Loss 곡선"(결과물, 시각화 가이드)처럼 Dev, Val을 쓴다. 이 README는 규칙대로 Validation으로 적었다.
- **피쳐 생성 시점**: 체크포인트 4는 "피쳐 생성은 분할 전에 수행하고"라고 한다. 지연값처럼 과거 값만 쓰는 피쳐는 문제가 없지만, 분할 전에 만든 피쳐가 경계 너머의 값을 쓰지 않는지는 체크포인트 3(Look-ahead Bias 방지)과 함께 따로 확인해야 한다. 명세에는 이 경계 처리 방법이 적혀 있지 않다.
- **오차 분석 "최소 기준"**: 기능 요구 사항 5의 제목은 "오차 분석 태그 체계 및 최소 기준"인데, 그 아래에는 태그 카테고리 표만 있고 건수 기준은 없다. 건수는 최종 결과물의 "최소 30건 이상"에만 나온다(결과 예시는 "오분류된 50장").
- **30건 이상과 Few-shot 데이터 크기**: 클래스당 50장 미만으로 학습하면 Test 셋에서 오분류가 30건 이상 나오지 않을 수 있다. 30건을 Test 셋에서만 채워야 하는지, Validation 등 다른 구간의 오분류도 포함해도 되는지 명세에 없다.
- **시계열 증강 범주**: "시계열 증강은 적용 금지/주의 범주를 반드시 확인한다"고 하지만, 어떤 기법이 금지이고 어떤 기법이 주의인지 범주 목록은 명세에 없다.
- **제공 CSV 파일**: "인터넷 불가 시 제공 CSV 파일 사용 가능"이라고 하지만, 그 CSV가 어디서 제공되는지는 적혀 있지 않다.
